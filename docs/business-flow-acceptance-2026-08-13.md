## 2. 验收范围与验证依据

本次验收以“业务是否能由不同角色完整操作并形成可追溯结果”为核心，不只检查页面能否打开。主要覆盖：

1. 登录、角色菜单、路由守卫和数据权限。
2. 人员档案、批次、板块、服务站和导师关系。
3. 课程创建、场次安排、人员分配和员工课程查看。
4. 培养计划创建、任务下发、员工提交、管理员审核。
5. 考试作答、交卷、考试结束后自动发布成绩。
6. 评价模板、月度方案、评分任务生成和评分人范围配置。
7. 多导师平均分、跨服务站按在站天数加权、培训评价。
8. 月度汇总生成、核对、发布和员工查看。
9. 后端、前端自动化测试以及前端生产构建。
10. 生产服务器健康状态和网站首页只读检查。

测试数据全部写入隔离数据库。验收结束后，隔离数据库、测试后端进程、测试文件和临时工作树均已清理。

## 4. 已验证的关键业务闭环

### 4.1 培养任务闭环

```text
管理员创建培养计划
  → 编排计划任务
  → 启用计划
  → 按批次预览并下发
  → 员工查看任务并提交成果
  → 管理员在待审核队列审核、评分和填写意见
  → 任务完成并计入月度任务成果分
```

### 4.2 考试成绩自动发布闭环

```text
管理员发布考试
  → 员工在规定时间内作答并交卷
  → 后台完成客观题自动评分
  → 考试开放期间员工成绩保持不可见
  → 整场考试结束后定时任务自动发布
  → 员工在成绩页面查看结果
```

本流程验证了成绩发布依据是“整场考试结束时间”，不是“某位员工交卷时间”。

### 4.3 月度综合评价闭环

```text
创建评价模板
  → 应用到批次和月份
  → 发布月度评分方案
  → 生成导师、站点、培训评分任务
  → 按全员、批次或板块配置评分人
  → 各评分人从个人待办独立评分
  → 系统汇总考试和任务自动分、多评分人平均分、跨站点加权分
  → 生成月度汇总草稿
  → 管理员核对并发布
  → 员工查看正式结果
```

## 5. 当前主要问题

### 5.1 P0：员工“我的课程”页面没有加载数据

**现象**

- 管理员可以成功创建课程、场次并分配员工。
- 员工首页能够显示一个近期课程。
- `/api/v1/sessions` 也会返回该员工的课程场次。
- 但员工“我的课程”页面始终显示 0 个课程安排。

**原因**

`frontend/src/views/MyCoursesView.vue` 定义了 `load()`，也导入了 `onMounted`，但没有注册 `onMounted(load)`，因此页面首次打开时没有请求课程、场次和签到数据。

**业务影响**

员工无法从课程主页面进入课程安排、签到和课件学习，是当前影响课程业务实际使用的最高优先级问题。

**建议**

1. 补充页面初始化加载。
2. 增加“管理员分配场次后员工课程列表可见”的端到端测试。
3. 同时验证空状态、加载失败和重新加载提示。

### 5.2 P1：课程和培养计划页面刷新或直接访问返回 404

**现象**

通过左侧菜单进入页面正常，但直接输入地址、刷新浏览器、打开收藏地址或恢复会话时，部分页面返回后端 JSON 404，例如：

- `/courses/manage`
- `/courses/my`
- `/courses/learning`
- `/training-plans/...`

**原因**

后端 `SpaController` 已为一级路由、`/exams/{path}` 和 `/evaluation/{path}` 转发 `index.html`，但没有覆盖课程和培养计划多级路由。

**业务影响**

用户刷新页面、使用书签、共享链接或浏览器崩溃恢复时会认为网站故障。

**建议**

1. 补齐课程和培养计划的 SPA fallback。
2. 对所有前端路由执行“直接访问 + 刷新”自动化检查。
3. 在 Nginx 和 Spring Boot 两种部署入口下分别验证 fallback 行为。

### 5.3 P1：评分范围规则可能清除未匹配人员的默认评分人

**现象与代码风险**

当前重新应用范围规则时，会先移除同月份、同评分项下每个未锁定任务的全部活动评分人，再应用匹配到的最高优先级规则。如果管理员仅创建某个批次或板块的局部规则，而没有配置全员默认，未匹配人员可能变成未分配。

界面已经提示“推荐先设置全员默认”，但程序没有把它作为保护条件。

**业务影响**

局部调整可能意外影响其他批次或板块，导致评分任务遗漏，而且管理员不一定能立即发现。

**建议**

1. 保存规则前展示影响预览：匹配员工、匹配任务、替换评分人、变为未分配的数量。
2. 没有匹配范围规则时，保留任务原有默认评分人。
3. 如果操作会产生未分配任务，要求二次确认或禁止保存。
4. 增加规则覆盖后的完整性检查和未分配告警。
5. 评分任务应保存生成时的批次和板块快照，避免员工后续调动改变历史月份归属。

### 5.4 P1：不可逆操作缺少二次确认

**已发现操作**

- 考试“提交试卷”会直接提交，没有最终确认和未答题数量提示。
- 月度评价“发布”会立即发布并锁定，没有展示最终分、员工和月份的确认摘要。

**建议**

- 试卷提交前显示已答题数、未答题数、剩余时间和“提交后不可继续作答”。
- 评价发布前显示员工、月份、综合分、缺失项、版本及“发布后员工可见并锁定”。
- 对发布、重开、缺项豁免等操作写入更明确的审计说明。

### 5.5 P1：数据库迁移依赖特定排序规则

**现象**

使用 `utf8mb4_unicode_ci` 创建全新数据库时，Flyway V8 在比较 `challenge_task.title` 和 `training_plan_task.title` 时出现排序规则混用错误。改用 `utf8mb4_0900_ai_ci` 后，V1 至 V27 可以正常完成。

**业务影响**

生产环境当前正常，但新环境部署、灾备恢复、自动化测试库和开发环境初始化可能失败。

**建议**

1. 在正式建库脚本中明确统一字符集和排序规则。
2. 统一所有表、文本字段、JDBC 连接和 Docker MySQL 配置。
3. 增加“从空数据库执行全部 Flyway 迁移”的持续集成检查。
4. 调整 V8 比较语句，避免对环境默认排序规则产生隐式依赖。

### 5.6 P2：评价模板配置过于集中

新建评价模板把五类评分项、满分、综合权重、站点汇总方式、季度权重、加扣分上限、重点任务和重点考试放在一个长表单中。功能完整，但对非专业管理员学习成本较高。

建议改为四步式配置：

1. 选择基础模板或预设方案。
2. 配置月度评分项与综合权重。
3. 配置重点任务、重点考试和站点规则。
4. 查看计算示例、权重合计和校验结果后保存。

### 5.7 P2：站点评价任务统计口径容易误解

测试中可能同时显示：

- 员工/任务：`1/2`；
- 范围配置评分人数：`0`；
- 评分人覆盖：`2/2`。

这是因为两个站点负责人通过站点职责自动分配，而不是通过范围规则分配。功能正确，但统计名称容易让管理员认为数据矛盾。

建议分别展示：

- 范围规则评分人；
- 站点职责自动评分人；
- 已覆盖任务；
- 未分配任务。

### 5.8 P2：前端首次加载性能仍可优化

生产构建成功，但存在约 502 KB 和 1.09 MB 的大代码分块告警。

建议按课程、考试、评价、人员模块进行异步路由分包，并检查 Element Plus、导出和文件预览相关依赖能否按需加载。

### 5.9 P3：浏览器控制台存在 favicon 401

每次打开页面时，`/favicon.ico` 返回 401。它不影响业务，但会制造无效错误日志。

建议将 favicon 作为公开静态资源，或在安全配置中明确放行。

### 5.10 P2：单账号只能拥有一个角色

当前 `sys_user.role` 是单值。现实中同一人员可能兼任导师、站点负责人或培训管理员，现有方案需要创建多个账号。

建议中期评估“用户—角色多对多”模型，并继续通过权限点和数据范围控制具体能力。该调整影响认证、菜单、权限矩阵和存量数据，不建议作为小修直接实施。

### 5.11 待独立补充：课件跨格式安全预览验收

本次业务流程验收没有重新上传 Word、PDF、PPT、OFD 四种真实文件进行跨格式渲染验证，因此本报告不对四种格式的当前生产预览效果作新的确认。

建议建立独立验收用例，至少覆盖：

- 四种格式上传、转换、逐页预览和异常文件处理；
- 原文件下载接口不存在或无法绕过；
- 姓名、工号动态水印；
- 权限校验、短时访问地址、防盗链和缓存策略；
- 管理端学习人数及员工查看次数、时长统计；
- 员工端只显示已学习/未学习，不展示次数和时长。

## 7. 建议补充的自动化验收用例

1. 管理员分配课程场次后，员工“我的课程”立即可见。
2. 每一个前端路由可以直接访问并在刷新后保持正常页面。
3. 员工交卷后成绩不可见，考试结束定时任务运行后自动可见。
4. 两名导师只看到各自待办，全部提交后才形成正式平均分。
5. 局部批次或板块评分规则不会意外清除其他人员评分人。
6. 跨站月按服务站变更日期正确计算天数和权重。
7. 五个启用评分项未齐全时不能正常发布；齐全后可以生成、发布和锁定。
8. 员工只能看到已发布结果，不能访问评价管理工作台。
9. 从空数据库执行所有 Flyway 迁移必须成功。
10. Word、PDF、PPT、OFD 文件可以安全预览且不存在原文件下载通道。
