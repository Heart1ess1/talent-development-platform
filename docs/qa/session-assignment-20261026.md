# 场次人员安排改造与验收记录

日期：2026-10-26。实现与验收均在本地进行，未发布生产；数据库验收使用单独创建的 MySQL 8.4 容器和合成员工数据。

## 已实现行为

- 原右侧抽屉替换为居中大弹窗，桌面左右两栏、移动端单栏页签，现有人员优先展示。
- 候选名单由服务端筛选、分页，不再只加载和缓存前 100 人；每页支持 20/50/100 人。
- 姓名/工号、届别、班级、班级职务、所属板块、服务站、双导师、学历、院校、专业筛选；分类字段支持多选，字段内为“或”、字段间为“且”。查询、重置按钮在筛选区域之外固定展示。
- 本页全选、全部筛选结果全选、跨页和跨筛选保留、去重及逐人排除。全部结果在点击时解析为固定的人员快照。
- 右侧完整人员名单支持独立搜索、签到/变更状态筛选、分页、批量移除和撤销。停用历史员工仍展示，已签到员工不可移除。
- 新增和移除先进入草稿，底栏显示变更前后人数；关闭保护、统一保存、失败保留草稿及网络结果不明时核对后再操作。
- 新增/移除统一事务，名单冲突检测，员工状态和数据权限校验，审计记录。人员调整、场次编辑/删除、自助/人工签到均先锁定场次，员工锁按 ID 排序。
- 继续使用现有人员安排表及唯一约束，没有新增数据库迁移。原新增和单人移除接口保留响应格式，并复用统一业务校验。

## 接口契约

前缀为 `/api/v1/sessions/{id}`，均要求 `course:manage`，人员查询和变更均受现有人员数据范围约束。返回沿用 `ApiResponse` 封装。

| 接口 | 请求/响应 |
|---|---|
| `GET /assignment-state` | `records`（人员及必要组织/签到信息）、`baselineHash`、`enrolledCount`、`attendanceCount` |
| `GET /enrollment-candidates` | `page`、`size` 及筛选字段；返回 `records/total/page/size` |
| `POST /enrollment-candidates/resolve` | 筛选 JSON；返回全部命中的简要人员记录 |
| `POST /enrollment-changes` | `{addIds, removeIds, baselineHash}`；返回 `{added, removed, state}` |

筛选字段：`keyword`、`batchIds`、`classIds`、`classPositionIds`、`businessUnitIds`、`stationIds`、`mentorIds`、`skillMentorIds`、`educations`、`school`、`major`。GET 数组用重复的同名参数传递。候选人员按工号和 ID 排序，仅包含在用且尚未安排人员，不返回身份证、电话等无关资料。

名单/签到发生变化返回 409；非法人员、停用新增或签到移除返回 400；无权限返回 403；场次不存在返回 404。整批校验失败不会产生部分变更。

通过 Playwright 操作本地真实前后端和 MySQL，不以接口模拟代替正常流程；仅在验证断网、响应丢失和 503 重试时注入网络故障。

- 233 名候选员工可以完整查询，第 101 人通过姓名/工号与多选班级、院校、专业组合找到。
- 本页全选与跨页保留正确；全选 233 人后排除 1 人，统一保存实际新增 232 人、移除 1 人。
- 左侧筛选和请求失败不隐藏右侧已有安排；已签到和停用历史人员的展示及操作限制正确。
- 关闭继续编辑保留草稿，放弃关闭不修改数据库；右侧批量操作分别处理原有、新增和已签到人员，撤销后计数恢复。
- 第二个请求真实修改名单后，原草稿保存返回 409，刷新名单且保留未生效草稿，再次保存成功。
- 服务端已保存但响应丢失时，自动读回实际名单确认成功；保存及读回均断网时锁定编辑，恢复后核对并完成保存。
- 1920×1080、1366×768、390×844：弹窗、底栏、分页均在视口内，弹窗无整体横向溢出；桌面显示两栏，移动端显示一个列表并可切换。
