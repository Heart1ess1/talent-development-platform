# 评分、答辩与办理时限改造

## 已实现的业务规则

- 任务评分、考试分值、人工评价、答辩、历史导入和加扣分支持两位小数；整数请求继续兼容。超过两位小数的原始评分拒绝保存，不依赖数据库隐式舍入。
- 分数输入和持久化使用十进制，任务多人评分平均值按 HALF_UP 保留两位；加权换算保留中间精度，结果和 Excel 显示两位。空成绩与零分分开处理。
- 每届固定第一、第二、第三、第四季度四次答辩。按培养进度设置场次，再明确对应一个评价季度，支持跨自然年；同届不同场次不能对应同一季评，不能新增第五场。
- 新模板将月度五项日常评分和季度答辩分开设置。月度项合计100%；季度答辩默认关闭、权重0%、满分100。启用后，月评汇总占季评的比重为100%减答辩权重。
- 季评分＝三个月月评按内部权重汇总 × 月评占比 ＋ 答辩成绩/本场满分×100 × 答辩占比。答辩不再重复计入月评；启用但缺答辩时，仅季度待完善。全过程保留中间精度，最终四舍五入到两位。
- 答辩页面的批次、场次、板块、班级、姓名/工号、状态和查询按钮同一行展示；窄屏在筛选栏内部横向滚动。四场次卡片展示对应季评，列表支持录入、校验发布、修订、历史和导出。
- 导入绑定所选场次，按“场次＋文件哈希”幂等；工号精确匹配并保留前导零，空成绩不作零分。逐行修正后整批审核，已有成绩须显式修订。成绩导出保持Excel数值类型与两位格式。
- 每员工每场次只有一个有效成绩。场次有过成绩发布后，对应季度锁定；成绩仍可修订。答辩更正只生成关联季度修订，不新建三个月月评版本。原正式季度保留到关联审核通过。
- 导航顺序为“评价工作台 → 评价模板 → 评分任务”，后接月度评分、答辩评价和关联修订审核。

### 使用顺序与历史兼容

1. 在“评价模板”中设置月度权重、季度三个月内部权重、季度答辩开关/占比/满分，再应用到培养批次和生效月份并发布方案。
2. 在“答辩评价”选择本届，设置四个场次分别对应的季评季度。例如第一季度答辩可对应2026-Q4，其余对应2027-Q1、Q2、Q3；此处仅为示例，不自动认定实际培养安排。
3. 选择场次后人工录入或导入最终成绩，校验发布，再在结果中心生成并发布季度结果。已有季度结果的更正进入“关联修订审核”。
4. 旧模板/方案的MONTH解释及已发布快照保留。旧月度答辩记录仅用于追溯，不直接猜测其对应四场中的哪一场。使用新季度规则须调整模板中的月度项至100%，应用并发布新方案；不静默重新分配历史权重。历史评价导入仍可保留原答辩分项和原总分。

## 时限与个人机会

培养任务、考试和评价评分任务共用三个时限类型：

| 类型 | 开始 | 截止 |
| --- | --- | --- |
| IMMEDIATE，下发即开始，默认 | 实际下发/发布生效 | 指定日期时间 |
| OFFSET，按基准日期偏移 | 下发/发布生效 | 基准日期加天数，当日23:59:59 |
| MANUAL，手动设置起止时间 | 指定开始时间 | 指定截止时间 |

统一按北京时间及秒精度判断，开始时可办理，截止时停止办理。考试草稿不会启动开放窗口。课程场次和签到不变。

管理员通过“调整时限/重新开放”填写原因、查看影响预览后保存。结束的任务和考试可立即或预约重新开放。整体调整覆盖全部人员的截止及归属，个人额外机会次数保留；已交答卷不恢复作答，整体延长也不增加已开始答卷的答题时长，缩短不得侵占其已获得时间。

个人机会只作用于指定员工；评价评分任务定位到指定员工、评价项和评分人。任务成功提交后、考试成功创建新答卷后、补评分成功保存后消耗一次。上传失败和续考不重复消耗。数据库唯一约束与事务共同防止重复创建或消费。

整体重开不重置考试普通次数；个人补考独立于普通次数。任务取最新审核通过成绩，补交等待评分时保留旧有效分；考试按最高有效已发布成绩取分。历史提交、答卷、答辩版本和补评分前的评价均可追溯。

## 计分归属与发布版本

- 新建任务及考试按截止月份计分。历史考试保留迁移前的归属，截止调整时再采用新规则。
- 整体跨月调整迁移全部人员的该项来源；个人特批只迁移该人的来源，撤销未使用机会恢复整体归属。同一来源不会在两个月重复计分。
- 导师、站点和培训评价的归属月份不随评分窗口移动。
- 已发布月份固定使用当时方案。新模板用于尚未发布的月份；关联修订按原月份的原方案、新月份有效方案计算。
- 同一员工尚未完成的关联修订合并审核；批量操作会合并重叠的修订组。原正式快照在成组发布前保持有效并标记待修订。
- 原月、新月及相关已发布季度进入修订组；刷新时也补入新近发布的关联季度。尚未发布季度不阻塞本次修订。
- 发布会重新计算并核对审核令牌；来源数值或修订代次发生变化，需要重新审核。组内月评、季评在同一事务中替换正式版本，旧版本转为历史。
- 缺评分可以由管理员填写原因并核定综合分；缺方案须先配置。导师等原角色和范围限制保留，已发布人工评价仅开放本次被授权的评分任务。

## 主要接口

- 现有任务、考试、评价输入扩展小数和时限字段。培养任务继续兼容 deadline、ABSOLUTE 等旧请求，新增公共字段别名。
- `/api/v1/evaluation/defenses/sessions`：按届读取四场次；`PUT /sessions/{batch}/{stage}`设置对应季度并携带版本号。
- `/api/v1/evaluation/defenses`：按sessionId查询、草稿录入、历史、校验发布、导入与导出。
- `/api/v1/schedules/{TASK|EXAM|EVALUATION}/{id}`：详情、影响预览、版本控制的整体调整、个人机会授予与撤销。
- `/api/v1/evaluation/revisions`：关联组查询、刷新、缺项核定与成组发布。
- 计划任务使用稳定 dispatchKey；迁移前的任务以原始下发日期快照回填兼容标识，调整 deadline 不改变下发身份。
