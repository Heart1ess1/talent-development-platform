# 月度评价 ABC 绩效使用与发布说明

## 使用流程

1. 进入“综合评价 → 月度评分 → 绩效划分”，选择月份、培养批次。
2. 单独填写当月 A/B/C 比例，合计 100%，保存。系统不会复制上月比例。
3. 核对名单。默认纳入该批次当前在培员工；不参评须填写原因，恢复参评后重新预览。需要更新人员时显式点击“刷新参评名单”。
4. 点击“重新计算并预览”，处理缺项。管理员可填写豁免原因和核定综合分，0 分属于有效成绩；正式答辩成绩缺失须先通过答辩任务发布，不允许人工核定绕过。
5. 核对目标人数、实际人数和比例，确认同分扩档提示，再统一发布成绩与等级。
6. 员工在“我的评价”查看本人正式等级；管理端可导出全组 Excel。历史无等级的结果显示“未划分”。

## 划分与修订规则

- 同月份、同培养批次独立划分，综合分按两位小数降序排名；加扣分、核定分沿用现有评分规则。
- 目标人数先取比例乘人数的整数部分，剩余名额按小数余数降序分配，同余数按 A、B、C 顺序。
- 同分组以首位名次分档，同分全部进入较高档；零名额档位跳过。10 人按 20/70/10 分配时目标为 2/7/1，第 2、3 名同分时实际为 3/6/1。
- 搜索、等级筛选、分页不会改变参评名单或分母。全组任何人缺少有效分数都会阻止正式发布，不将缺分默认为 0 或 C。
- 发布后名单固定。管理员重开或来源成绩修订会创建新绩效版本；任一人员变化都重新预览全组，显示原分、原等级及新结果。原正式版本保持有效直到统一发布。
- 原关联修订涉及多个月份或批次时，预览会完整展示关联绩效和月评，一次事务统一发布；不允许拆开发布导致前后矛盾。
- 同一员工同一月份固定属于一组，调换当前培养批次不会悄然迁移已保存的参评范围。
- 首次启用只支持没有既有正式成绩的批次月份，已发布历史成绩、历史导入结果不自动补算。

## 本地验证与上线准备

新增数据库迁移为 `V52__monthly_performance_grading.sql`，使用独立组表、成员表、月份范围表；当前正式版本和草稿版本均有唯一约束。迁移只新增结构，不回填历史等级。

集成测试必须指向可丢弃的 MySQL 数据库，在后端目录执行：

```powershell
$env:ABC_TEST_DB_URL='jdbc:mysql://localhost:13316/talent_abc_test?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false'
mvn.cmd -q test
```

使用默认开发数据库账号时只需设置上述 URL；独立账号可通过 `DB_USERNAME`、`DB_PASSWORD` 配置。测试会创建独立业务夹具，不可使用生产库。未设置 `ABC_TEST_DB_URL` 时仅跳过 MySQL 专项集成测试，普通单元测试照常执行。

前端检查在前端目录执行 `vue-tsc -b`、`vitest run`、`vite build`（使用项目现有包管理运行器）。浏览器验收应覆盖管理端设置/排除/预览/发布，以及员工本人等级查看。

上线前核对当前环境最高迁移版本和工作区其他未发布改动，使用下一个有效版本号处理冲突；备份数据库及当前前后端制品，先在预发布库验证迁移和构建。发布后检查健康接口、未登录接口 401、真实管理账号统一发布和员工本人查询；生产业务验收须单独记录。若需回退，先禁用新功能入口，使用与当前数据库兼容的应用制品，保留已发布绩效快照；不要直接删除新增数据表。
