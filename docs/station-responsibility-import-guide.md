# 站长与区域经理批量导入

管理员、超级管理员进入“人员管理 → 站长与区域经理管理”，点击“下载模板”。三个标签页共用同一模板和导入入口。

## 填写模板

“负责人配置”工作表仅五列：服务站、站长姓名、站长工号、区域经理姓名、区域经理工号。模板预填当前启用服务站，负责人信息为空。“填写说明”中的示例不会参与导入。

- 姓名和工号必须成对填写。工号同时为登录账号，请按文本填写以保留前导零。
- 填写的人员名单替换该站同级负责人；姓名和工号同时为空表示保留原配置。未涉及的站点保持原配置。
- 一人负责多站，在每站填写相同姓名、工号。一站多人，重复该站多行，同级人员合并为完整名单；完全重复的关系合并并提示。
- 服务站必须存在、启用且名称完全一致。姓名不能超过64字，工号允许1～64位字母、数字、点、下划线和连字符。
- 已有账号必须姓名一致、角色一致且启用。角色、姓名、停用或员工关联冲突应先通过账号管理核实处理；导入不会自动转换角色、改名或启用账号。
- 清空负责人使用原有“调整负责人”功能，模板空白不代表清空。
- 文件仅支持.xlsx，最多5MB、1000条非空数据行、500组“服务站＋角色”，单站同级最多50人，不支持公式。

## 校验、交接与确认

1. 点击“导入负责人”，选择文件并“校验并预览”。预览阶段不创建账号，不改负责范围。
2. 检查有效行、跳过行、重复关系、新建／复用账号、变更站点和请假责任。使用“仅看错误”“仅看变更”集中核对。
3. 存在错误时整批不能导入。下载错误明细，按原始行号及建议修正原文件，移除已选文件后重新上传。错误明细不是导入模板。
4. 核对当前及导入后负责人、账号创建与复用明细。替换人员涉及待审批或未销假的请假责任时选择同站同级接任人；一名接任人时默认选中，多名时必须选择。新账号也能接任。
5. 填写本次调整原因（最多500字），点击“确认导入”。账号、范围、责任和审计统一提交，任一步失败均回滚。
6. 完成后查看结果，三个标签页和顶部统计自动刷新。被替换人员账号保留，历史审批记录保留。

预览有效期30分钟。账号、服务站、负责人或请假责任变化时必须重新预览。网络超时先点“查询导入结果”；重复确认同一批次返回原结果，不会重复建号或交接。关闭预览即取消操作，预览数据七天后清理。

## 新账号登录

新账号的用户名为工号，初始密码为工号后六位；不足六位使用完整工号。例如20260001对应260001，001234对应001234，1234对应1234。首次登录进入账号设置，修改为8～64位新密码后才能使用业务功能。

已有账号继续使用原密码，原有首次改密状态保持现状。新建负责人不生成新员工培养档案。本版本不支持同一工号兼任站长和区域经理。

## 验证命令

先准备独立的MySQL 8.4测试库，将`STATION_IMPORT_TEST_DB_URL`和`LEAVE_TEST_DB_URL`设为该库JDBC地址（默认测试用户talent，密码通过`DB_PASSWORD`配置）。禁止指向生产库。

```powershell
cd backend
mvn test
cd ../frontend
pnpm test
pnpm build
```

测试报告中两个集成测试类必须实际执行，不能把按环境条件跳过的测试计为通过。浏览器验收应覆盖模板下载、错误文件、预览、交接、确认、账号登录与改密、负责范围及手机宽度展示。
